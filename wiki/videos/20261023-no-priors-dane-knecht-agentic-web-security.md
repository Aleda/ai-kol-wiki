## 安全：发现能力扩散，修复也要扩容

- Knecht 称过去需要全员应对的重大漏洞事件，从大约每年一次变得接近每周一次；他预测未来约 18 个月，工程团队超过一半的时间会用于安全，随后压力可能缓解。这是他的观察与预测，未提供可核实的统一统计口径（[00:02:04]–[00:03:04]）。
- 他称部分重大漏洞由使用 agent 的高中生发现，主持人称之为「agent kiddies」。他同时提到漏洞赏金，因此这里说的是**漏洞发现能力扩散**，不能把所有发现者等同于恶意攻击者（[00:05:08]–[00:06:08]）。
- 面对全面隔离关键系统的悲观设想，他更相信行业协作与 zero trust 能改善处境；这不是对关键基础设施安全的保证（[00:06:08]–[00:07:08]）。
- 他的办法从减少代码和攻击面开始，辅以更安全的语言、运行时及形式化验证；他承认当时的 AI 容易产生冗长和复杂度，需要工程师、安全团队及对抗性审查共同把关。Cloudflare 将内部 RFC 和实践整理成 Codex 文档及供 agent 审查使用的原则（[00:09:09]–[00:12:12]）。
- 他说公司当时有一个红队，预计到下一年年底可能增至四或五个；他倾向先加强漏洞发现，让压力推动修补流程自动化，同时继续交付新功能。**发现能力增加不自动证明修复吞吐量足够**，这是该方案需要检验的环节（[00:35:27]–[00:37:29]）。
- 对网络安全模型的开放问题，他认为攻击者和大型公司终会取得能力，封闭会把需要防御能力的大量人排除在外；主持人同时指出开放防御能力可能也会开放攻击能力。两者是尚未解决的权衡（[00:38:30]–[00:39:30]）。

### 与既有观点对照

- [Greg Brockman](20261015-no-priors-greg-brockman-cyber-spend-drug-physics.md) 认为安全支出可能大幅超过软件支出；Knecht 讨论的是工程时间与暂时的安全投入高峰。**支出、token 预算和工程时间不是同一指标**，不能直接判为相同预测（[00:07:08]–[00:08:08]）（[Brockman 期](20261015-no-priors-greg-brockman-cyber-spend-drug-physics.md) [00:34:15]）。
- [Misha Laskin](20261009-no-priors-misha-laskin-beam-open-model.md) 也主张开放有助于安全；Knecht 的补充是防守能力的分配问题，二人的判断都不能单独证明开放的净安全效果（[00:38:30]）（[Laskin 期](20261009-no-priors-misha-laskin-beam-open-model.md) [00:54:53]）。

## Agent Web：访问方式与内容收入

- Knecht 将当下称为「混乱的中间阶段」：人和 agent 使用同一套面向人的网页，agent 解析页面会产生额外成本，也不一定经过原有广告模式。他预计会出现更适合机器消费内容的方式，并非声称两套网络已经建成（[00:13:12]–[00:14:12]）。
- 他设想 agent 决定是否读取并按内容方现有广告 CPM 等价基准付费，需要支持高频小额交易的支付基础设施。**这是商业模型设想，不是已经验证的创作者收入**（[00:14:12]–[00:15:13]）。
- 他介绍 Cloudflare 的内容变现网关、agent 钱包和稳定币，以及与 OpenAI 合作的 Signals 项目，称后者帮助 agent 发现新内容、减少反复抓取；他也承认个人 agent 的技术和商业模式尚未成熟（[00:16:15]–[00:18:16]）。这也是 Cloudflare 作为基础设施供应商的产品叙述。
- 他给创作者的成功标准是收入覆盖基础设施开销并支持生计，而非仅实现付费接口（[00:19:18]）。

## Cloudflare 内部：平台、工作流与预算

- 他称 Cloudflare OS 起点是治理客户及内部数据在 AI 工具中的流动，同时把公司构建软件的惯例写给 agent；公司把它作为参考架构开放，供其他组织 fork。他称销售及一般行政团队使用多于工程团队，原因之一是空白聊天界面缺少业务上下文和引导（[00:20:18]–[00:23:18]）。
- 他将组织重组与 AI 改变工作方式联系起来，并明确提到有同事离开。例子是产品经理发送客户邮件：原来涉及 BI、营销和营销运营三个团队，现在由工具辅助圈选、改写，仍需经理批准后发送；这是公司个案，不能据此推算净岗位变化或普遍效果（[00:24:18]–[00:25:20]）。
- token 使用方面，他主张最终智能路由：例如前沿模型规划、开放模型执行，再由前沿模型审查；当时仍多靠人工。他说公司重交付结果、不设 token 排行榜，并在个人每天约 300 美元时提醒本人、500 美元时通知经理、1000 美元时通知 VP；这是自述的提醒机制，非硬上限（[00:27:21]–[00:28:22]）。
- 他称公司此前约有 200 名实习生，观察到带实习生的经理采用 AI 更快，因此在一年内招聘约 1000 名实习生；主持人提到公司约 5000 人。两者时间口径不同，不应理解为 1000 人同时在岗。他还说一个接收员工需求并返回 skill 文件的邮箱，早期实际由实习生协助处理（[00:29:23]–[00:30:24]、[00:32:24]）。
